## 1. 这个项目在做什么（不读历史也能懂的版本）

**数字员工形态的数据管家。** 它不是 ETL 工具，也不是 BI：它是一个会发邮件问人、
会等人回复、会被审批挡住的 Agent，在自己的 lakehouse 里整理出一份可信数据，
顺带把「谁能看哪些列」也理清楚。

三件事定义了它，缺一件这个项目就没有卖点：

1. **限制不靠模型自觉。** 所有约束（工具分级、审批票据、动作指纹、SQL 护栏、
   预算、WIP）都实现在 Hermes 的 `pre_tool_call` 钩子里。不写进 system prompt。
   ——因为限制一旦依赖模型听话，就永远证明不了「Agent 绕不过」。
2. **Agent 写不了「决定」。** 审批 callback 是独立进程 + 独立数据库账号，
   `decisions` 表对 Agent 只有 `SELECT`。同进程的话列级 GRANT 形同虚设。
3. **它会等人，而且等很久。** 一条线可能是：发现表 → 找 Owner → 发邮件 →
   等 8 小时 → 回复 → 请求审批 → 等 1 天 → 恢复 → 落 bronze。
   同时并行十几条，各自挂在不同的人身上。所以状态必须在库里，不能只活在进程里。

### 数据怎么流

```
源系统（只读、禁 join、限流）
   └─ ingest_table (L3，要 Owner 批) ─► iceberg.bronze   原样落地
        └─ apply_cleaning_rule (L2，要 Steward 批) ─► iceberg.silver  原值留 <列>_raw
             └─ publish_gold (L3) ─► iceberg.gold   对外；没分类不发布、_raw 不出去
                  └─ grant_read (L3) ─► rules.json   谁能进来；看到什么由分类决定
```

### 人怎么参与

```
门禁拦下 ─► 发审批邮件（两枚一次性签名链接）─► 人点链接
    │                                              │
    │                                    独立进程写 decisions
    │                                              │
    └─ 记「这条线在等谁」进 runs 表 ◄──────────────┘
                │
        cron monitor 发现有决定了 ─► 唤醒 Agent 再调一次工具
```

**正文里写「我同意」不算数**，必须点链接 —— 防的是转发链接被误点，
以及「邮件正文可以伪造」这件事本身。

### M5 为什么先动记账

驱动反转（脚本从**扮演 Agent** 改成**扮演人**）真正挡路的不是脚本，是这个：

```
旧： 脚本 → runs.RUNNERS["ingest_table"] → Pipeline → gate（PENDING）
                    └── 回来之后由它调 runs.suspend / runs.finish
                        ↑ 这个包装就是脚本伸出去的胳膊

新： Hermes → tool_call("ingest_table") → gate（PENDING，工具 handler 根本没跑）
                                              └── 没有任何人记这条线
```

所以先把记账挪到门禁一侧（`_track_suspend` / `_track_close`），挂在已有的
`_notify_async` 旁边：一个告诉人，一个告诉登记表。**两个都是观察者，
不改变放行与否** —— 铁律 1 禁的是把「限制」散出去，不是禁止记录发生了什么。

## 4. 关键决策

- **`grant_read(principal="claw")` 按 L4 拒绝，且不发审批。**
  工具名不足以描述一个动作：同一个 `grant_read`，开给真人是正常业务，
  开给自己就是提权。只按工具名分级的话，L4 那组 `grant_self` 有一个换名字的绕过口。
  实现成 `policy.py` 里的 `ARG_DENY` 表（**加禁令 = 加一行**）。
  不发审批是因为——自我提权不是「问一下人就行」的事，问了反而给了一次被误批的机会。

- **`publish_gold` 的两条前置：没分类不发布、`_raw` 不出去。**
  没有分类就推不出遮蔽规则，analyst 读到的是明文；`<列>_raw` 是清洗前的原值，
  跟着发布等于清洗白做。这两条是**操作本身的正确性前提**，不是门禁 ——
  别把两层混起来。

- **发件永远留在我们这边，收件并进 M5。**
  铁律 2 要求 callback 是独立进程，它身上没有 Hermes，回执只能自己发；
  第二份删不掉的前提下，把门禁那侧改走 Hermes 的 adapter 只会从「一份」
  变成「两份不一样的」。收件的差距是真的（IMAP / 附件 / 验真），
  但 M5 本来就要把入站落到它的 adapter 上。

- **`tracing.py` 不与 Hermes 的 observability 合并。**
  它只支持 Langfuse，而且没有 `WAITING_FOR_HUMAN` 这种跨进程、跨天的 span 概念。

- **恢复用 `monitor_script` 而不是每分钟点模型。**
  恢复必须让 Agent 自己再调一次工具（这才叫驱动反转），所以要点模型；
  但一分钟一次显然不行。Hermes 的 `monitor_script` 每 tick 先跑一个便宜脚本、
  按字节哈希输出，**没变就整个跳过 agent 运行**。于是实际成本是一次 SQL 查询。

- **搬 cron 会丢掉一条性质，这是自觉的取舍。**
  `ops/scheduler.py` 原注释写着「独立于 Agent 运行：Agent 挂了催办也不能停」。
  搬进 Hermes 之后不成立。换来的是作业锁、claim fence、按 `next_run` 恢复、
  失败投递、输出留存 —— 那 89 行全都没有。丢掉的由 **M6** 补回来。

## 5. 踩过的坑 —— 全是同一个形状

**闸门读的量根本没人写，或者闸门挂在网络后面。失败方式都是安静的。**
这个项目已经在这个形状上摔过六次，新加的断言专门盯这一类。

| # | 现象 | 真相 |
|---|---|---|
| 1 | `publish_gold` 的 `_raw` 检查「通过」 | 它挂在 Trino 查询后面，Trino 一挂根本走不到 —— 测试看到「调用失败了」照样算过。纯参数判断提到连库之前 |
| 2 | 预算兜底从来没触发过 | `usage_ledger` 里只有 `persona.py`（扮演人的模型）的花销，Claw 自己一分钱没记，读到的永远是 0 |
| 3 | `record_usage` 在本地永远静默失效 | 它自己连 DSN，没有 DSN 就 `return` |
| 4 | Postgres 起不来但没人发现 | `init-steward.sql` 少建五张表，`GRANT ON asset_semantics` 指向不存在的表，`psql -f` 断在那里 |
| 5 | 「网络内部匿名探测」整条静默 SKIP | 它走 `docker exec datalaker-scheduler-1`，而 M4 之后那个容器默认不再守护。**而且它本来就是假绿**：只判「异常 = 被挡住」，那么「容器压根连不到 trino」也算通过 |
| 6 | `ops/resumable.py` 作为 monitor 每分钟报一次错 | 全新库里 `runs` 表还没建，`resumable()` 是只读打开的不建表。monitor 崩掉每分钟就是一次错误 tick |
| 7 | 白名单可以被打穿 | `sender_allowed` 只比对 `From:`，而 `From:` 是发件人自己写的。把 From 填成王姐的地址就能进来 —— 她有权回答口径、转介角色 |

第 7 条的修法照 Hermes 的规则来（它在自己的 adapter 里引了 GHSA-rxqh-5572-8m77）：
只认收件服务器 prepend 的**第一条** `Authentication-Results`，
DMARC pass / SPF pass 域对齐 / DKIM `header.d` 对齐 三选一，没有这个头就不通过。
顺带修掉 `fetch_unread` 把重复头折叠成最后一个 —— 恰好是攻击者塞进来的那条。

## 10. 不要做的事

- **不要把限制写进 system prompt。** 那一段只放「什么时候该停下来问人」的**引导**，
  模型可以不听而门禁照样拦得住。有一条断言专门检查提示词里没有「你不可以」。
- **不要在工具 handler 里判审批。** 被拦时 handler 根本不跑；写了就是把限制
  散进业务代码。有断言在 grep `find_valid` / `is_denied`。
- **不要 fork Hermes。** 允许改，但尽量不改 —— 这个 checkout 最后要变成产品本体。
- **不要写一个没跑过的断言数。**
- **不要把「异常 = 被挡住」当成安全断言。** 先证明连得上，再证明进不去。
- **Docker 连不上时不要发散排查。** 默认原因就是外置盘掉线：确认盘 → 重启 Docker →
  还不行就问人。`builder prune` / legacy builder 在只读文件系统上全部无效。
