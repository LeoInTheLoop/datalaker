## 3. 关键决策

### 决策 7：审批邮件异步发送，且发信失败不影响拦截

`pre_tool_call` 有超时上限且**超时会 fail closed**，不能让 SMTP 往返拖垮 hook。
因此 `_notify_async()` 起后台线程发信；请求本身已经落库，
邮件只是通知，失败只记 `MAIL_FAILED` 事件。

**动作依然不会执行**——通知没送达不等于门被打开。

> `TODO(R4)`：换成 outbox 表 + worker。催办与逐级升级本来就需要重扫未决请求，
> 届时线程方案要退场。

### 决策 8：`request()` 返回 `(id, created)`

用于区分「新建请求」与「已有待决请求」，避免重复发信
（readme 5.5：一封邮件只问一个决策）。

### 决策 9：被拒绝的查询同样入负载账本

`Agent 尝试过什么危险操作`是审计的一部分，也是 Demo 里最有说服力的一页。
`connector.LEDGER` 同时记录 `OK` 与 `REJECTED: <原因>`。

### 决策 11：gate 必须自己 fail closed（安全隐患修复）

`agent/agent_runtime_helpers.py:3487` 的 dispatch 层写着：

```python
except Exception:
    block_message = None      # ← 异常冒到这里，工具会被放行
```

单个 callback 的异常虽由 `invoke_hook` 吞掉，但**不能把安全性寄托在上游异常处理的细节上**。
`gate()` 已改为整体 try/except，任何异常返回 `[GATE_ERROR]` block。
新增断言 2 条（组件异常时连 L0 也挡住）。

### 决策 12：block 消息会被包成 `{"error": ...}`

Hermes 被 block 时返回给模型的是 `json.dumps({"error": block_message})`，不是纯文本。
`tests/test_pending_semantics.py` **4/4** 验证了这个格式下模型行为不变：

- `{"error": "[PENDING_APPROVAL]..."}` → 不重试，回复「已提交，等待审批」
- `{"error": "[DENIED]..."}` → 不重试
- 纯文本对照组 → 同样不重试

**挂起语义对返回格式不敏感**，这一条原本是风险，现已排除。

```
Trino /v1/info    无凭证 → HTTP 200
--user=attacker   能 CREATE TABLE
MinIO 凭证        admin / password
```

### 决策 14：堵上自我提权后门（不能等 R3）

`policy.py` 原本没有针对 Agent 自身权限的条目——**这是所有门禁的后门**：
Agent 可以先给自己提权，再去做别的事。

已将以下全部标为 L4（永不自动）并补 5 条断言：

```
modify_own_role / grant_self / modify_role_assignment
alter_access_policy / rotate_own_credential
```

### 决策 15：无人认领 = 保持最小权限

readme 新增 11.6「凭证生命周期与初始授权」，回答了一个此前没答的问题：
**Agent 要访问 lakehouse 就要凭证，而这套 lakehouse 是它自己建的，谁授权？**

- Lakehouse 初始 owner 是 **Sponsor**（他发起的项目，责任推卸不掉）
- 初始凭证通过**一次性 HMAC 链接**告知，复用审批令牌机制，明文不进邮件/日志/上下文
- Sponsor 走完 T+12d 升级仍无回应 → 平台**保持最小权限**：只读源、只写 bronze，
  **不发布 gold、不对任何人开放**

> 最危险的降级是「没人管，那先开着吧」——那正是「财务表全公司 187 人可读」的成因。
