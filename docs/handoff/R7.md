## 3. 关键决策

- **`get_task_state` 现在就实现，而不是留给 B2。** 三份 skill 都以「先查状态」开头，
  没有这个工具那句话就是空话，模型只能靠回忆 —— 而它会把「上次好像申请过」当成事实。
  它只读 `runs` / `approvals` / `decisions`，Mission / Objective / Scope **不在里面**，
  返回里明说了这一点，免得模型拿这张表当项目目标的事实源。
- **状态词表放代码，不放文档。** skill 和报告都引用 `tools._TASK_STATES`；
  算不出来的状态原样报「未归类状态：x」，不兜底成一个像样的词。
- **`set_checkpoint()` 与 `suspend()` 分开。** `suspend` 对「已经在等同一份审批」是幂等的，
  「已批准 → 改成等窗口」正好落在那个幂等分支里写不进去 —— B3 要写 `approved_waiting_window`
  必须用前者。这是写 A5 的测试时撞出来的，不是设计出来的。
- **skill 引用的名字用代码派生的词表校验。** 反例词表（状态词、参数名、
  `STAGE_OPTIONS` 的 key）全部从 `_SCHEMAS` / `policy.py` 里取，不手写 ——
  手写的那份会烂掉，然后这条检查变成永远绿。已用假工具名做过反例验证。

## 4.5 D 组（2026-09-15 已实施，两条都不依赖 eval）

| 项 | 做了什么 | 验证 |
|---|---|---|
| **I03.11** 到点唤醒 | `runs` 加 `next_action_at`；`schedule() / unschedule() / due() / scheduled() / due_now()`；**未到点的线不进 `resumable()` / `retryable()`**（过滤在查询侧，所以 `resume_all()` 那条老路也守窗口）；monitor 增 `kind="due"`；恢复与收口清排期；`get_task_state` 报「到点再动：… （还没到）」 | `tests/test_due_wakeup.py` 18 项；突变反例：拿掉 `resumable()` 的到点过滤，两条断言立刻红 |
| **I08.09** 停止点接线 | monitor 增 `_observe()`（从治理库组装事实）+ `_stop_point()`，报 `kind="stop_point"` / `"blocker"`，带 deliverable 与 question，**不带 `waited`**（发一次，不每小时催）；cron prompt 教模型这两种是「停下来交成果」不是「继续干活」 | `tests/test_stop_point_wiring.py` 13 项 |

两处设计值得记：

- **三态，不是两态。** `stop_points` 原来靠 `c.get(k)` 判，键缺了就是 False ——
  「没到停止点」和「压根查不出来」长得一模一样。现在约定：缺键/假值 = 查过了没有，
  显式 `None` = 这次查不出来；`unevaluable()` 把后者报出来，`next_stop()` 跳过它。
  Trino 连不上时 `silver_ready=None`，不会被当成「silver 还没好」而永远不请人拍板。
- **还有两个键没有事实来源**：`priority_confirmed`（没有「哪些表优先」的确认记录）、
  `sample_reviewed`（没有「人看过清洗前后样例」的记录）。对应的停止点 1、3 判不了。
  测试断言这份缺失清单**正好是这两个** —— 补上来源时那条断言会提醒改。

- **`suspend()` 幂等挡住了改 checkpoint**（R7 §3 已记），这次又撞到同一形状：
  排期不能靠 `suspend` 写，所以 `schedule()` 独立。
