## 2. 关键决策

### 决策 22：元数据查询与业务查询是两类

`pg_index JOIN pg_attribute` 被「禁 join」误伤。
**不给护栏开 `purpose` 豁免**——Agent 可以声称自己在做 discovery。
改为把元数据查询也参数化：SQL 写死在 Connector，只传表名且先过标识符校验。
与 4.6「参数化优于自由 SQL」是同一条原则。

### 决策 23：AST 准入必须遍历整棵树

关键字匹配挡不住：多语句、注释分隔的 join、子查询里的 join、
CTE 内的写操作、`FROM a, b` 隐式 join。
反过来，注释里出现 "join" 字样不再误伤——**看结构不看字面**。
语法无法解析一律拒绝，不猜测意图。

### 决策 24：schema 漂移中止同步，不是自动接受

`schema_hash` 变化即抛 `SchemaDrift`。新增字段的业务含义属于业务知识，
Agent 不应自行决定要不要、怎么用（L2）。人确认后 `allow_schema_change=True` 继续。

### 决策 25：双重确认用令牌 stage 实现

`stage=click` 只发确认信，`stage=confirm` 才落库。
**链接被转发多少次都无所谓——确认信只到 approver 的注册邮箱。**
不依赖任何身份判断，比验证码轻、比 OAuth 简单。
内网部署时入口层已有身份，可用 `REQUIRE_DOUBLE_CONFIRM=0` 降档。

### 决策 26：归属由 header 确定，语义由分类给出

两件事分开，各用各擅长的。四层归属只有第 5 层标记 `certain=False`。
自动回复由 RFC header 确定性识别，且**不重置超时计时器**。
正文里的「同意」仍需点击签名链接才作数——
这让分类错误的代价从**安全事故**降到**体验损失**。

## 3. 踩过的坑

| 坑 | 教训 |
|---|---|
| `allow-insecure-over-http` + 8080 端口映射 | **自己引入的洞**：修复前匿名 POST /v1/statement 返回 200 能查任意数据。明文端口绝不能映射出去 |
| 加授权后 L0 冒烟全挂 | **加授权会打断所有既有访问路径**，运维与测试脚本必须显式报身份 |
| `rules.json` 里的 `_comment` | JSON 不支持注释，Trino 严格校验会拒绝未知字段导致启动失败 |
| 启用认证后 Trino 起不来 | 必须配 `internal-communication.shared-secret`，单机也不例外 |
| `DATASTEWARD_DSN` 是全局变量 | 一设就让所有测试走 Postgres，包括没装 psycopg 的 Hermes 环境。**测试必须逐段显式控制存储后端** |
| `VAR=x ( cmd )` | sh 中非法，回归跑到第 4 组就静默中断 |
| `sqlglot` 只装在 `.venv` | gate 新增依赖要同步到**所有运行环境**：系统 python3、容器镜像、Hermes 的 `.venv-h`（uv 建的，没有 pip，须用 `VIRTUAL_ENV=... uv pip install`）。漏一处就触发 fail-closed |
| `test_sync` 删了源数据 | 污染 `test_ingest_paths`。**跨测试的数据依赖必然出问题**，测试要自己准备数据 |
| `information_schema` 按权限过滤 | 只读账号看不到外键约束，改用 `pg_catalog` |
