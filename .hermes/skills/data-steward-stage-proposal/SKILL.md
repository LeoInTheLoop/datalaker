# 报告与提案

这个 skill 管**怎么写给拍板的人看**，里面是两件不同的事，别混：

| | Cycle 报告 | 阶段提案 |
|---|---|---|
| 什么时候 | 一个 Cycle 的时间或 token 预算到线 | 一轮做完、该决定下一步做什么 |
| 报什么 | 预算用了多少、完成了什么、在等谁、风险 | 三选一 + 你的建议和理由 |
| 产物 | 一封如实的报告 | 调 `propose_stage_decision` |
| 谁放行下一步 | 下一个 Cycle 要有人重新放行 | 拍板的人选一个选项 |

**阶段批准不等于下一个 Cycle 放行**，反过来也不成立。两件事分开说。

## 一、Cycle 报告：到线就报，报实话

Cycle 的时间和 token 预算由配置定，**由代码累计、到线时叫停** ——
不是你自己估的，也不该由你决定还能不能再做一点。到线时手上正在跑的动作
可以收尾，**但不开新动作**。

### 报告里必须有的几段

1. **预算与用量**：这个 Cycle 给了多少时间 / token，实际用了多少，
   报告本身预留了多少。数字来自真实的用量记录，**不要重算也不要估**。
2. **完成了什么**：接了哪几张表、确认了哪些口径 —— 具体到对象，不要写「推进了工作」。
3. **在等谁**：按人列。谁、等他什么、等了多久。这一段是给人看「该催谁」的。
4. **正在跑的**：如实单列。正在跑不是完成，也不是等人，**不要并进上面两段**。
5. **风险和已知限制**：包括你没做到的、数据里还没解决的问题。
6. **建议**：下一个 Cycle 该先做什么，以及**这需要谁来放行**。

拿不到的数字就说拿不到。**「本 Cycle 无进展，因为三件事都在等回复」是一份
合格的报告**；把等待写成进展不是。

### 别做的事

- 不要在报告里说「如无异议我就继续了」。下一个 Cycle 要有人放行。
- 不要因为快到线就把手上的活草草收尾或跳过核验。到线就报，没做完就说没做完。
- 报告发不发、什么时候发、到线之后还能不能动 —— 由代码决定，不由你决定。

## 二、阶段提案（周报）

一轮做完了，下一步做什么是**人的决策点**，不是你自行续摊。
这个 skill 管的是**怎么写**；能不能开下一轮由门禁管，你不用也管不着。

### 什么时候用

`data-steward-weekly-report` 这个 cron 作业每次运行时。上面的 `## Script Output`
里是已经算好的四段（本周完成 / 卡在谁那里 / 需要你决策 / 系统开销）——
那些数字是脚本查库得来的，**不要重算，也不要改写**。

### 你要做的

#### 1. 把四段压成一段小结

给拍板的人看，不是给你自己看。要能一眼看出：接了多少张、卡在谁那里
（点名到人和天数）、发现了几处问题。别复述整个表格。

#### 2. 调 `propose_stage_decision`

三个选项是固定的：

| key | 什么意思 |
|---|---|
| `push_unfinished` | 先把没批下来的追完，清洗下周再说 |
| `start_silver` | 接得差不多了，开始清洗轮 |
| `abandon_rest` | 剩下那几条别等了，记为已知阻塞项 |

参数：`summary`（第 1 步那段）、`recommend`（三选一，**必须给**）、
`reason`（为什么）、`decider`（谁拍板）。

#### 3. 建议怎么给

**只把三个选项摆出来不算提案** —— 那是把判断推回给人。你要选一个，
并且说清楚理由。几条参考：

- 口径还没裁决就开清洗轮 → 会返工，通常建议 `push_unfinished`
- 已接入的表覆盖了主要业务对象、且没有悬而未决的口径冲突 →
  可以建议 `start_silver`
- 某条线超过一周没有任何回应、且升级已到顶 → 那一条建议
  `abandon_rest`，但要写明「随时可重开」

理由要能被反驳。「我觉得可以了」不是理由，「3 条口径冲突还没裁决，
现在洗完还得重洗」是理由。

### 几条别做的事

- **不要自己开下一轮。** 你调完这个工具就该停下来做别的事。
  真去调 `apply_cleaning_rule` 会被门禁拒（`ROUND_NOT_OPEN`）——
  那不是 bug，是这条流程的定义。
- **不要重复发提案。** 同一轮的提案已经在等回复时，工具会告诉你
  「还没有人拍板」。再发一次只是重复打扰。
- **不要在正文里替人做决定**，也不要写「如无异议我就开始了」。
  正文写同意不算数，必须点链接 —— 这是防转发误批，不是刁难。
- **无进展也要发。**「本周无进展，因为 3 件事都在等回复」本身就是
  重要信息，而且正好说明该选 `push_unfinished`。
